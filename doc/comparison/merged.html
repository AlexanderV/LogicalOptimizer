Roadmap P0.2 · controlled cross-library benchmark

LogicalOptimizer vs. other libraries

One committed corpus of Boolean functions, run once in a single pinned Linux container. Every competitor number comes from an external tool run on the same inputs. Sizes, counts and verdicts are exact; timings are indicative and not compared here.

Where each competitor appears

The tools do different jobs, so each is compared only where it applies — no single table lists all of them.

01

Result size — multi-level

Fewer literals is better. LogicalOptimizer emits factored multi-level output; SymPy/PyEDA emit two-level DNF/SOP, so on structured functions ours can be far smaller. Beyond ~16 variables the truth-table tools exceed their 2ⁿ budget (skipped).

✓ fewer ours strictly smaller = equal tie timeout over budget skipped beyond 2ⁿ tool limit
02

Result size — two-level SOP

Apples-to-apples: ours result.DNF is the same kind of two-level form SymPy simplify_logic and PyEDA espresso produce, so equal counts are the correct outcome — ours reaches the same optimum wherever all three finish.

03

Equivalence proof via SAT

Each optimization is checked by solving the miter original XOR optimized: UNSAT ⇒ the optimized formula is logically identical to the original. Independent external solvers agree with our verdict on every function.

04

Exact model counting — #SAT

Satisfying-assignment counts computed three independent ways: our BDD/d-DNNF, the d4 exact counter (count-preserving per-function CNF), and LogicNG's BDD. Identical numbers cross-validate our counter. (c2d is proprietary and not in the container.)

All four tables share one committed corpus and one run. A tool over budget records timeout; an absent tool records pending — no number is ever fabricated.

Reproduce: docker build -t logicopt-p0p2 tools/comparison && docker run --rm -v "$PWD:/work" logicopt-p0p2
